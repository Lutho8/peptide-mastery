# Tracker production cutover — 22 August 2026

This record documents the cutover from the legacy Lovable-managed backend to the Peptide South Africa-owned Supabase project. It intentionally contains no credentials or personal data.

## Source and safeguards

- Source archive: PostgreSQL custom-format backup, 8,143,756 bytes.
- SHA-256: `4ec44ec7e03e5dedea1268bbad33fb3f1b14cecbd8b730e580c6a110a76438bf`.
- The import was first executed inside a transaction and rolled back after validation.
- Existing production identities were preserved. The one overlapping administrator identity was mapped to the existing company-owned account.
- Legacy refresh tokens and sessions were not imported; migrated users must establish fresh sessions.

## Production result

- 29 legacy accounts imported alongside the 9 existing accounts (38 total).
- 30 tracker profiles, 324 dose records, 282 audit records, 21 stacks, 9 lab-report records, and all other populated tracker tables reconciled.
- Primary keys, unique constraints, foreign keys, indexes, and tracker triggers restored before data commit.
- Referential-integrity checks returned no orphaned tracker records.
- The existing administrator account received the tracker administrator role.
- Private `lab-reports` and `progress-photos` buckets now have owner-scoped upload, read, update, and delete policies.
- NocoBase tracker integrations were retired. The first-party Supabase CRM is the active lead path.

## Historical file limitation

The database archive includes metadata and extracted results for nine historical lab reports, but PostgreSQL backups do not contain the corresponding Storage object bodies. A separate export of those nine private PDFs from the legacy Storage service is required if users must reopen the original documents. New uploads use the owned private bucket normally.
